Operating systems · adversarial search

Momus

It evolves the workloads that make classical OS algorithms behave as badly as they possibly can.

Textbooks show each scheduling or paging policy with one friendly example. Momus does the opposite: it searches automatically for the input that hurts the policy most, then measures how far it falls behind the best possible policy on that same input.

Method

How Momus works

Every domain plugs into the same loop. Only the simulator and the optimal reference change.

  1. 1

    Encode a workload

    A matrix of numbers: page references, process arrivals and burst lengths, disk cylinders, or heap requests.

  2. 2

    Simulate the policy

    Run the policy under attack on that workload and record its cost: faults, turnaround, head movement or memory.

  3. 3

    Score against optimal

    Divide by the cost of the optimal policy on the same input. The ratio is the fitness.

  4. 4

    Search for worse

    Random search, hill climbing, a genetic algorithm or MAP-Elites mutate the workload and keep what scores higher.

Scope

What it attacks

Every workload is scored by its empirical competitive ratio: the policy's cost divided by the cost of an optimal (or clearly stated reference) policy on the same input. A ratio of 3 means three times worse than the best possible.

Does the search matter?

Evolution beats random guessing every time

Four search methods attacked each of the 32 settings, 30 runs each. All three evolutionary methods beat random search in every setting (Vargha–Delaney A12 ≥ 0.99, p < 0.05). The surprise: a simple restarting hill climber was the strongest method most often.

Checking against theory

LRU gets close to its proven limit

Theory says LRU with k frames is never more than k times worse than OPT. The best hand-built attack (the cyclic adversary) gets near that limit on finite strings. Momus, with no hints, reaches 86 to 100 percent of the hand-built attack.

Rediscovered without being told

Known failures it found on its own

CPU · FCFS

Convoy effect

One long job arrives first and every short job waits behind it. Mean turnaround reaches 9.36× SRTF.

Paging · LRU

Cyclic adversary

Loop over k+1 pages so the page LRU just evicted is always the next one needed. Ratio 3.37 with 4 frames.

Paging · LFU

Stale-frequency trap

Pages used heavily early on stay in memory long after they stop mattering. LFU reaches 12× OPT, the worst paging result.

Disk · SCAN, C-SCAN

Edge travel

The arm sweeps to the end of the disk even when every request is close by. Up to 199× the optimal head movement, while LOOK stays under 2×.

Paging · FIFO

Belady's anomaly

Found in every hill-climbing run. The largest: 25 faults with 3 frames and 37 with 4.

Memory · buddy

Power-of-two waste

Buddy allocation can need 5.2× the live memory, against about 2.4× for the fit policies.

Reproduce it

Run it yourself

Pure Python with NumPy. The full study takes about 30 minutes on 4 cores.

# install and check the simulators against textbook answers
pip install -r requirements.txt
python -m pytest -q tests

# quick smoke test, then the full study and the figures
python -m experiments.run_all --quick
python -m experiments.run_all
python -m experiments.analyze
Momus is named after the Greek god of criticism and mockery. All numbers on this page come from the study's results files (4,380 runs). Code and paper: github.com/keshavkhandelwall/momus.
